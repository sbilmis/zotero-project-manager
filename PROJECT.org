* Goal
Keep Zotero as the source of truth and export selected collections into stable,
app-independent research workspaces. Preserve originals, annotations/notes,
filename/layout choices, and repeatable incremental updates.

Success means one standard workspace per selected collection, clear export
summaries, working Settings, and no app-specific folders, launchers, or upload
steps in the plugin. Users choose how to use exported files in other apps.

* Notes
** Current workflow
- Select a Zotero collection and export it to a permanent parent folder.
- Export Collection copies attachments according to settings; Export Collection +
  Annotations also generates annotation/child-note documents in the same workspace.
- Selecting Agentic_AI includes its descendants, not its My-AI parent or siblings.
- Existing workspaces retain their recorded filename and annotation layout.
- Re-export updates the same workspace. Ordinary exports do not prune old files.
- Use another app manually if desired; zpm does not index, upload, synchronize
  external app records, or create app-specific workspace copies.
- Hidden =.zpm/= files are exporter bookkeeping; keep them out of manual imports.

** Upgrading from the experimental previews
- Existing =Agentic_AI= and =Agentic_AI - NotebookLM= folders remain untouched by
  installation. Standard exports update only the selected standard workspace.
- Do not automatically remove old folders: external applications may still rely
  on them. Any cleanup of those folders/records needs a separate user request.
- Old notebook-link preferences are left dormant, not used or cleared.
- Removed CLI flags: =--to=, =--notebook-url=, =--devonthink-group=,
  =--prepare-only=, and =--profile=.
- Old standard named projects remain compatible. For a config project containing
  =export_profile = "notebooklm"=, review its output folder/layout and remove that
  setting only if standard export is intended. No automatic conversion is done.

** Future integration reconsideration (parked)
The prior automation/API research is historical, not a commitment to restore the
features. Revisit only with explicit approval and a demonstrable benefit beyond
opening an app and manually selecting files.

API status was checked on 2026-09-10: Google documented preview Enterprise notebook
creation/source APIs requiring Enterprise access and Google Cloud authentication.
That did not establish access for the user's personal Notebook account. Recheck
eligibility and current support before proposing any implementation. A Gemini model
API key alone was not the Notebook integration used here.

If an integration is later approved, keep its delivery adapter separate from the
standard exporter, verify end-to-end results/retries, and avoid duplicate folders
unless a genuinely different export format is explicitly requested.
