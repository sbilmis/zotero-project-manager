* Goal
Keep Zotero as the source of truth while making selected research collections,
attachments, notes, and annotations useful in two independent destinations:
Gemini Notebook and DEVONthink 4. Preserve Zotero originals and support safe,
repeatable exports.

Success means both destination actions work from Zotero, their limitations are
clear, and repeat exports do not create duplicate DT4 links. Evaluate Zotero MCP
as a separate next step for finding and organizing material before export.

* Notes
** Current handoff behavior
- Gemini Notebook: export supported sources and annotation sidecars to a flat
  workspace, open the saved notebook (or ask for a link on first use), and select
  the exact files in Finder. The user
  completes Add sources / Upload files or drag-and-drop. No API key, Chrome
  extension, or Google Drive setup is required for this route.
- DT4: choose a database/group and index exported files, preserving subfolders.
  Existing indexed paths are refreshed rather than duplicated. Keep the export
  folder permanently; it remains the storage location for those linked files.
- Neither route continuously watches Zotero. Re-export/send to pick up changes.
- Notebook uploads are snapshots and repeat uploads can duplicate sources.

** Notebook automation and API migration [2026-09-10 Thu]
Remembered links are now implemented in the plugin; the CLI independently
accepts =--notebook-url=. Creation, naming, and uploads remain manual.
The remaining enhancements are proposals, not implemented in the preview:

- Extend the current one-link-per-collection mapping only if multiple explicit
  account/provider destinations are needed. Do not infer ownership from titles.
- Offer browser-assisted creation and naming from the collection. First-time
  linking to an existing notebook already works.
- Evaluate the referenced Zotero/Chrome connector before building a new browser
  bridge. Its documented flow can create a notebook from the home page; upload
  may still require a genuine user click. Verify collection-based naming and
  compatibility with zpm's exported annotation sidecars separately.
- Keep browser automation opt-in. Use the user's normal login, do not extract
  cookies or replay private Google endpoints, and pause for login/consent.
  UI changes and partial uploads must produce a clear status and manual fallback.
- Track acknowledged notebook/source IDs and file hashes where supported. Do
  not retry an uncertain upload blindly or delete sources to reconcile a batch.

API status checked on 2026-09-10: Google documents preview Gemini Notebook
Enterprise APIs for notebook creation and file uploads. They require Enterprise
setup/licensing and Google Cloud authentication; account eligibility is unknown.
This is not a drop-in use of a normal Gemini API key or an established connection
to the user's personal notebooks. See the official references below.

If a supported Notebook API is available to the user's account and its use is
approved, replace the desktop/browser handoff with an API adapter. Preserve the
exported content and Zotero identity mapping, validate provider-specific formats,
and verify creation, upload completion, retries, and duplicate handling first.
Do not automatically migrate existing notebooks or remove the manual fallback.

Another no-Notebook-API option is a Drive-synced export folder with sources added
through Notebook's Google Drive picker. Google documents updates to already
imported Drive sources. This does not create a notebook or automatically add new
files from a folder. Verify stable Drive file IDs across zpm's atomic replacements
before promising ongoing updates; cloud storage requires an explicit choice.

** Proposed MCP-assisted workflow
Ask a research question, retrieve relevant Zotero papers and annotations, review
the proposed shortlist, and create/curate a collection with explicit approval.
Then use zpm to send that collection to Gemini Notebook or DT4.

MCP would help decide what belongs in the collection; zpm handles the exported
files. The evaluated MCP project does not itself supply our Gemini upload or DT4
handoff. Generated summaries and citations still need source verification.

* Decisions
- Keep Gemini Notebook and DT4 as two separate destination options.
- DT4 only; never fall back to DT3.
- Copy/export outward from Zotero. Do not move, edit, or index Zotero originals.
- Use the extension-free, manual-final-upload Notebook route for this preview.
- Keep source preparation separate from delivery so an approved official API
  can replace the handoff later without rewriting the collection exporter.
- Implement remembered notebook links first, as approved by the user. No browser
  extension, API connection, or automatic cloud upload is enabled.
- Index exported files in DT4; do not silently import copies or prune DT4 records.
- Keep Zotero MCP as the single NEXT item; do not implement or install it now.
- Start an MCP pilot read-only. Collection, note, tag, or metadata writes are
  optional later capabilities, not part of the initial pilot.
- The user approved committing and pushing this work to the existing GitHub
  branch. Publishing a release, merging to main, or changing the public update
  feed is a separate decision. Installation and live workflow checks remain open.
